# Настройка Supabase — 2 октября 2026

Проект pebnjhbofduhzkduaaxt сопоставлен с адресом тестовой игры.
Подключение Supabase подтверждено, проект ACTIVE_HEALTHY.

Применены миграции:
- mobile_guest_trials_and_quotas: две гостевые таблицы, RLS, резервирование 10 ходов, ограничение запросов;
- restrict_turn_balance_rpcs_to_server: add_turns/spend_turn/handle_new_user доступны для прямого исполнения только серверной service_role;
- enable_http_for_connection_verification: HTTP-расширение в extensions для проверок соединения без чтения секретных файлов.

Развёрнут guest-ai: проверяет пользовательский JWT через Supabase Auth, допускает только анонимных пользователей,
ограничивает запросы серверными квотами и списком моделей, использует существующий OPENROUTER_KEY.
GET возвращает только состояние подключения и доступность моделей, без секретов и пользовательских данных.
GET не вызывает генерацию. POST требует действующую гостевую сессию.

Старый ai сохранён с его фактической логикой cost (фон cost=0 не списывает игровые ходы).
Добавлен отказ для анонимных сессий: они используют только лимитированный guest-ai.
Нужные CORS-заголовки уже были корректными в живой функции; прежний файл репозитория отставал от сервера.

Серверный ключ проверен через OpenRouter /api/v1/auth/key: HTTP 200. Значение ключа не читалось и не возвращалось.
По живому /api/v1/models подтверждены:
- openai/gpt-6-luna
- z-ai/glm-5.3-flashx
- z-ai/glm-5.3
- anthropic/claude-sonnet-5.5
- google/gemini-3.1-flash-lite

Для Sonnet исправлен точный ID в селекторе. Не выбирается пакетный вариант :batch.
По каталогу обычный Sonnet 5.5 стоит $2/$10 за миллион input/output, :batch — $1/$5.
Наличие модели и действующего ключа не доказывает качество конкретного игрового ответа.

Оставшийся блокер: /auth/v1/settings сообщает external.anonymous_users=false.
Коннектор не предоставляет изменение настроек Auth. Пользователь должен включить Anonymous Sign-ins:
https://supabase.com/dashboard/project/pebnjhbofduhzkduaaxt/auth/providers
После переключения нужно проверить гостевую сессию и один настоящий запрос выбранной модели.

При публикации этого отчёта анонимный вход всё ещё выключен. Полный оплаченный игровой запрос ещё не проверен.
Проверены HTTP 200 диагностики, наличие гостевых таблиц/RLS, закрытый прямой доступ к гостевым RPC и доступность всех пяти ID.
Советник Supabase отмечает отсутствие клиентских RLS policies у гостевых таблиц: это намеренно, таблицы обслуживает только сервер.
Источник: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy
Предыдущий публичный EXECUTE для административных функций баланса исправлен:
https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable
