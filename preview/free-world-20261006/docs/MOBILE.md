# Мобильная версия: горизонтальный экран и гостевые ходы

Открыть: https://zhank478.github.io/grand-strategy/mobile.html?v=2

Карта занимает экран; слева пять разделов, сверху страна/дата/казна, снизу
выбор периода и следующий ход. Остальные экраны открываются по одному.
Вертикальная ориентация показывает просьбу повернуть телефон.
Регистрация, магазин и плашка аккаунта скрыты. Автоматические вызовы
регистрации отключены только в мобильной версии; код аккаунтов сохранён.

## Включение 10 гостевых ходов с настоящим ИИ

Из GitHub нельзя включить настройки и развернуть функции в вашем Supabase.
До выполнения этих шагов интерфейс и карта работают, но гостевые ИИ-ходы
недоступны. Уже авторизованные обычные аккаунты используют существующий /ai.

1. Supabase → Authentication → Settings: включить Allow anonymous sign-ins.
2. Supabase → SQL Editor: выполнить supabase/mobile_guest.sql.
3. Supabase → Edge Functions: создать guest-ai, вставить
   supabase/functions/guest-ai/index.ts и Deploy.
   Отключить Verify JWT на шлюзе: функция сама проверяет пользователя
   через auth.getUser. Используется уже существующий секрет OPENROUTER_KEY.

Без почты и пароля браузер молча создаёт анонимную сессию. Сервер хранит
10 игровых ходов на гостя; новая партия и перезагрузка не пополняют лимит.
Один игровой ход резервируется один раз перед изменением календаря.
Фоновые запросы профилей не списывают игровые ходы.
Сохраняется защита от повторного нажатия и повтора идентификатора запроса.
Гостевые запросы ограничены на сервере: 20 подготовительных и 200 всего,
фиксированная недорогая модель, изображения выключены.
Гостевая сессия хранится в браузере; очистка данных создаёт нового гостя.
Это пробный режим, а не защита от создания новых пользователей.

Регистрация позже может быть возвращена отдельной кнопкой и переводить гостя
в постоянный аккаунт. Сейчас новые формы входа не показываются.
Бонус обычного аккаунта в существующей схеме — 40 ходов; он сохранён.

## Проверки

Проверены синтаксис клиентского JS, наличие DOM-элементов и отсутствие
повторяющихся id. Проверки гостевого клиента с подставным сервером:
ровно 10 ходов; остановка 11-го; отсутствие продвижения календаря при
недоступном сервере или неудачном резервировании; защита от двойного
нажатия; сохранение существующего маршрута ИИ для зарегистрированного аккаунта.

Нужно проверить на физическом телефоне: горизонтальный экран, следующий ход,
карта/жесты, страна, действия, дипломатия, новости, экономика, общество,
советник, история, сохранения, экранная клавиатура, редактор.
Серверный SQL и функция подготовлены, но не выполнены/развёрнуты через GitHub.
